# 잔여 작업 구현·적대적 검토 결과

기준일: 2026-10-19 · 브랜치: `feat/rankseo-track-a` · 시작 커밋: `2b0a357`

구현 커밋: `ae393b1`(보고서·모바일·테스트), `925094f`(DB 분리).

## 구현 결과

- 진단·점유율 보고서의 ID 조회와 최신 조회를 활성 프로젝트로 제한했다. 다른 프로젝트 및 프로젝트 없는 행은 모든 형식에서 404를 반환한다. 같은 시각의 최신 결과는 ID로 안정적으로 정렬한다.
- `/api/reports`와 `/api/change-items/report`가 app/proxy 계정을 입력 해석 전에 검증한다. 성공과 오류 응답에 `private, no-store`와 `nosniff`를 적용한다.
- 수정 결과 보고서의 같은 URL 재조회·실패 후 재시도를 복구했다. 프로젝트 변경 즉시 이전 결과·다운로드를 지우며, 요청 세대와 AbortController로 이전 요청의 늦은 응답을 무효화한다.
- 수정안의 충돌 확인 입력·버튼을 모바일에서 세로로 배치했다. 긴 원본·수정 값·전달 이력·URL이 카드 안에서 줄바꿈된다. 주소 불일치 경고의 설명도 긴 URL 때문에 한 글자씩 배치되지 않게 했다.
- `src/lib/db/index.ts`를 1,191줄에서 56줄로 줄였다. 초기 스키마와 5개 버전 구간으로 마이그레이션을 분리했다. 버전·SQL·실행 순서·기존 export·HMR 연결 캐시는 보존했다. 추가 마이그레이션은 없다.
- 공급자 실패 테스트에 남아 있던 실제 공개 페이지 조회를 mock으로 고정했다. 네트워크 속도에 따른 5초 타임아웃이 발생했으며, 응답 분류·호출 횟수·복구·기존 데이터 보존 검증은 유지했다.

## 적대적 검토

`mattpocock-skills:code-review`의 두 독립 검토와 직접 반례 검증을 수행했다.

### Standards

함수 50줄 제한을 넘은 `ChangeReportClient` 1건을 확인했다. 조회 상태를 `useChangeReport`로 분리해 훅 44줄·화면 함수 19줄로 해결했다. 재검토 미해결 0건.

마이그레이션 31개 객체와 초기 SQL의 원문을 시작 커밋과 비교했다. 별도 AST 검토에서도 SQL/template 문자열 35개가 동일함을 확인했다. 이동된 기존 마이그레이션 본문을 재작성하지 않았다.

### Spec

프로젝트 변경 이벤트와 이전 응답의 JSON 본문 완료가 effect 정리 전에 겹치는 P1 경합 1건을 확인했다. 같은 작업 구간에서 이벤트와 본문 완료를 실행하는 테스트로 실패를 재현한 뒤, 이벤트 시점에 요청 세대를 즉시 증가시키도록 수정했다. 이전 요청의 성공·오류·finally 모두 세대를 검사한다. 재검토 미해결 0건.
