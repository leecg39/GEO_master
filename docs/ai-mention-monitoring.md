# AI 언급 모니터링

`/monitoring`은 기존 응답 점유율 측정의 저장된 원문을 조회하는 전용 화면이다. 새 측정은 `/share` 또는 `/automation`에서 실행한다. 모니터링 화면을 조회하거나 내보낼 때 LLM을 호출하지 않는다.

## 화면

- 기존 대시보드를 유지하고 사이드바에 **AI 언급 모니터링** 메뉴를 추가한다.
- 프로젝트 요약, 기간, 월별 완료 실행 수, CSV 내보내기와 설정 링크를 표시한다.
- 좌측 질문에는 원문, 기준·현재 언급률, 언급한 AI 서비스 수(최대 4개), 평균 등장 순위를 표시한다. 모바일에서는 목록을 접을 수 있다.
- 전체 성과는 주별 언급률, 기준·현재 변화, 4축 레이더와 모델 비교 표를 제공한다.
- 질문 상세는 자사와 등록 경쟁사의 현황, 실행별 추이, 브랜드 선택, 더보기를 제공한다. 자사는 항상 표시하며 기본 그래프에는 자사와 상위 5개 경쟁사를 포함한다.
- 차트에 대응하는 수치 표를 펼쳐 볼 수 있다. 미측정 구간은 선으로 연결하지 않는다.
- 질문 목록은 원문 검색(최대 200자), 등록 순·현재 언급률순·증감순 정렬, 25개씩 페이지 나누기를 제공한다. 검색은 목록만 바꾸고 집계와 선택된 상세는 유지한다. 하락은 감소 문구와 음수 부호로 표시한다.
- 질문의 자사 차트 포인트, 실행별 표, 측정 시점 선택기로 과거 응답을 선택한다. 경쟁사 색·선 패턴은 브랜드 ID에 고정되고 자사와 선택 포인트는 강조한다.
- 선택 시점 아래에 4개 서비스 카드를 유지한다. 카드 펼치기 시 해당 서비스 원문을 조회하며 검색 조건·반복 응답 선택, 현재 사전 기준 강조, 복사, 출처를 제공한다.
- 기존 질문 API와 낙관적 동시 수정 검사를 사용한다. 질문 세트가 없으면 사용자 저장 시 `모니터링 질문` 세트를 만든다.

## 모델과 지표

모델은 **ChatGPT (`openai`), Claude (`anthropic`), Gemini (`gemini`), Grok (`grok`)**으로 고정한다. Perplexity API나 선택 항목을 추가하지 않는다. 다른 provider의 응답은 집계하지 않는다.

| 항목 | 정의 |
| --- | --- |
| 언급률 | 브랜드를 언급한 성공 응답 수 / 전체 성공 응답 수 × 100 |
| 응답 단위 | 저장된 질문 × provider × 반복 응답 슬롯 |
| 실패·거절 | 분모에서 제외하고 별도 집계 |
| 중복 언급 | 한 응답에서 같은 브랜드는 한 번만 집계 |
| 주간 집계 | 응답 수 기준 가중 집계, KST 월요일 시작 |
| 평균 순위 | 등록 브랜드가 응답에 처음 나타난 순서의 평균. 검색 순위가 아님 |
| 언급 모델 수 | 해당 브랜드를 언급한 서로 다른 provider의 수. 실제 모델 버전 수가 아님 |
| 기준·현재 | 기간 내 첫 번째·마지막 완료 실행. 완료 시간이 같으면 실행 ID로 정렬 |
| 단일 실행 | 현재 값만 표시, 기준과 변화는 `null` |
| 미측정 | 해당 실행에 질문/모델이 없으면 `null`; 응답은 있으나 언급이 없으면 0% |

저장 당시 요약 수치를 사용하지 않고 `geo-core`의 사전·매칭 엔진으로 원문을 다시 분석한다. 현재 프로젝트의 자사명, 사용 가능한 별칭, 등록 경쟁사를 사용한다. 화면에 **현재 브랜드 설정 기준 재집계**를 표시한다. 사전 변경 전후의 값이 달라질 수 있으며, 수동 검수 결과나 검색 순위 지표와 동일한 지표는 아니다.

`measure_results`에는 질문 ID가 없으므로 **저장된 질문 원문 전체의 SHA-256**을 조회 키로 사용한다. 같은 원문을 가진 등록 항목은 모아서 표시하고 수정할 질문 세트를 선택할 수 있다. 질문을 수정하면 이전 원문의 결과는 그대로 남으며 새 원문과 합치지 않는다. 등록은 해제되었으나 선택 기간에 측정 이력이 있는 질문도 표시한다.

## API

`GET /api/monitoring`

| 파라미터 | 설명 |
| --- | --- |
| `start`, `end` | `YYYY-MM-DD` (0001~9999년), KST 포함 날짜. 기본 최근 84일. 최대 366일 |
| `question` | 질문 원문 SHA-256, 생략하면 전체 성과 |
| `projectId` | 활성 프로젝트 확인용. 다른 프로젝트 ID는 409 |
| `format` | `json`(기본) 또는 `csv` |
| `comparison` | `all`(기본) 또는 `same`. 최근 완료 실행과 동일한 저장 조건만 집계 |

완료 실행만 읽으며 완료 시간이 없는 기존 데이터는 생성 시간을 사용한다. 지원 외 provider 응답만 있는 실행은 비교 기준·월별 실행 횟수·추이에서 제외한다. 원문이 아예 없는 기존 실행은 미측정 상태로 유지한다. SQLite의 시간대 없는 UTC 날짜도 명시적 UTC로 정규화한 뒤 KST 주간 집계에 사용한다. 100개 같은 임의의 실행 수 제한으로 기간 데이터를 잘라내지 않는다. 날짜로 조회를 제한하고 응답 원문을 순회하여 집계한다.

JSON은 `project`, `range`, `questionSets`, `runCount`, `conditions`, `endpoints`, `monthlyRuns`, `overview`, `providers`, `weeks`, `questions`, `selected`, `selectionMissing`을 반환한다. 인증 문맥을 확인하고 `Cache-Control: private, no-store`를 적용한다. 기존 전역 활성 프로젝트 모델의 범위 검사를 따르며 새로운 사용자별 프로젝트 소유권 체계를 도입하지 않는다.

CSV는 동일한 서버 집계 함수를 사용한다. 전체 화면에서는 전체·모델·주별·질문 요약을, 질문 선택 시에는 해당 질문의 모든 등록 브랜드와 실행별 추이를 내보낸다. 차트 체크박스는 시각적 표시만 제어하며 CSV의 브랜드를 제외하지 않는다. 내보내기는 화면에 표시된 시작·종료일과 질문 키를 명시해서 요청한다. UTF-8 BOM, 셀 따옴표 이스케이프, 수식 삽입 방어를 적용한다. 없는 질문을 요청하면 다른 보고서로 대체하지 않고 CSV는 404를 반환한다.

질문 세트 생성 API에 선택적 `projectId` 범위 검사를 추가했다. 기존 호출 방식은 유지된다. 새로운 DB 마이그레이션은 없다.

질문 편집창이 프로젝트 전환 등으로 사라지면 진행 중인 요청을 중단하고 후속 질문 생성이나 이전 저장 완료 콜백을 실행하지 않는다. 이미 서버에 반영된 변경을 되돌리는 기능은 아니며, 다시 조회하면 실제 저장 상태를 확인할 수 있다.

## 실행별 응답 근거

`GET /api/monitoring/responses`는 `projectId`, `question`, `runId`, `start`, `end`, `comparison`을 받는다. `question`과 `runId`는 필수다. `provider`는 4개 서비스 중 선택하며 `limit`은 기본 20·최대 100, `cursor`로 다음 원문 페이지를 조회한다. 집계와 같은 인증·활성 프로젝트·기간·완료 실행 검사를 적용한다.

- `summary`, `providers`는 필터·페이지와 무관하게 해당 질문·실행 전체 응답에서 계산한다. 페이지는 `items`만 제한한다.
- 커서는 프로젝트·질문·실행·provider·기간·비교 조건에 묶인다. 다른 문맥의 커서는 422다.
- 질문 키를 프로젝트의 정확한 원문으로 해석하고 `question_text = ?`로 조회한다. 동일 키워드가 들어간 다른 질문을 섞지 않는다.
- 원문은 HTML을 실행하지 않는 텍스트다. 집계와 같은 현재 브랜드 사전으로 하이라이트하며 URL만으로 언급을 추가하지 않는다.
- 출처는 `cited`(명시 인용), `inline`(본문 URL), `searched`(검색 결과)를 구분한다. 저장 당시 분류를 명시하고 자격 증명이 없는 HTTP(S) 링크만 노출한다. 서버는 출처를 방문하지 않는다.
- 일반 응답과 웹검색 요청은 같은 서비스 내부 조건이다. 실제 모델명과 검색 수행 기록을 따로 표시한다. 웹검색을 요청했어도 일반 응답으로 수집된 슬롯은 그대로 설명한다. 과거 기록 부족은 확인 불가로 표시한다.
- 실패·거절은 성공 분모에서 제외하고, 미측정과 원문 없는 과거 실행도 각각 표시한다.

화면 URL의 `run`은 상세 선택 전용이며 집계 API·기간 CSV로 전달하지 않는다. 실행 선택은 `replaceState`, 질문 전환은 `pushState`를 사용한다. `run`이 없으면 해당 질문을 마지막으로 측정한 실행을 선택한다. URL의 실행이 기간 밖이거나 없으면 오류와 복구 버튼을 표시한다. 과거 실행을 선택해도 상단 기간 비교·현재 브랜드 현황은 유지한다.

## 측정 조건 비교

`comparison=same`은 조회 기간의 가장 최근 완료 실행을 기준으로 질문 원문, provider, 요청·반환 모델, 검색 요청·적용 모드, 반복 번호와 슬롯 구성이 같은 실행을 남긴다. 제외 수를 화면과 CSV에 표시한다. 실제 검색 결과·답변·모델의 내부 동작까지 동일하다는 의미는 아니다.

원문·요청 검색 모드·모델·현대 수집 버전 등의 기록이 부족하면 같은 조건으로 단정하지 않는다. 최근 실행이 이러한 상태라면 `same`은 422이며 UI에서 선택을 막는다. 전체 조건에서는 기준·최근 차이와 기간 중 다른/불명 조건 포함 여부를 안내한다. 기존 DB 스키마를 사용하며 마이그레이션과 새로운 LLM 호출은 없다.

## 검증

```sh
npx vitest run tests/monitoring.integration.test.ts tests/monitoring-responses.integration.test.ts tests/monitoring-client.test.tsx tests/question-pool.integration.test.ts
npm run typecheck
npm run build
```

핵심 회귀 검증은 가중 분모, 실패·거절, 현재 별칭 재집계, 원문 보존, KST 날짜 경계, 미측정과 0% 구분, 프로젝트 격리, 인증, CSV 일치·안전성, 오래된 요청 무시, 질문 수정 충돌, URL 선택 복원을 포함한다. 스크린샷 예시는 별도 테스트 DB의 합성 데이터이며 실제 측정 성과가 아니다.
