# Qshop 접목 전후 비교 분석

작성일: 2026-09-09

**GEO Master에 페이지별 수정안·승인·큐샵 수동 적용 안내·공개 URL 재검증이 연결됐다. 가장 큰 가치는 진단 결과를 실제 수정 작업과 연결하고, 반영 여부를 근거로 확인하게 된 점이다. 큐샵 자동 게시나 검색·매출 성과 개선까지 완료된 상태는 아니다.**

**비교 기준**

- 이전: 현재 브랜치의 마지막 커밋 `948cd04`(2026-09-05)에 저장된 관련 코드.
- 이후: 2026-09-09 현재 작업 트리의 Qshop 관련 코드, 적용 문서 및 검증 기록.
- 현재 작업 트리에는 기존 WordPress·구독·분석 관련 미커밋 변경도 함께 있다. 전체 변경을 Qshop의 성과로 계산하지 않고, 적용 문서와 관련 코드에서 확인한 범위만 비교했다.
- 최초 기획서의 기준 커밋은 `647fc41`이지만, 현재 브랜치에 이미 들어 있던 GEO Blocks·GeoPageSpec·연구 보조 기능은 신규 Qshop 기능으로 계산하지 않았다.
- 이번 분석은 로컬 구현 기준이다. 사용자의 실제 큐샵 사이트에 배포·적용됐다는 의미가 아니다.

**기능과 운영 방식 비교**

| 비교 항목 | 접목 이전 | 접목 이후 | 실무상 의미와 한계 |
|---|---|---|---|
| 전체 작업 흐름 | 진단·콘텐츠 생성·측정 모듈이 있고 GEO Blocks에도 초안·승인 기능이 있었음 | 사이트 진단 안에서 실제 페이지 수집 → 수정안 → 승인 → 적용 안내 → 재검증을 연결 | 페이지 단위로 무엇을 왜 바꾸고 어디까지 처리했는지 추적 가능. 큐샵 반영은 사람이 수행 |
| SEMForge 사이트 진단의 수집 | Firecrawl Map으로 URL 목록을 발견한 뒤 본문 요청 없이 HTTP 200·크기 0·추정 깊이를 저장 | URL 발견과 본문 수집을 분리하고 실제 HTTP 상태·최종 URL·본문·메타데이터·수집 시각·해시를 저장 | 목록에 있는 URL과 실제로 읽힌 페이지를 구분. 기존 별도 `/audit`에는 실제 HTML 진단이 이미 있었음 |
| 진단 점수 | URL 수와 이슈 수를 사용한 가정 기반 건강 점수 | 수집에 성공한 페이지의 기술 규칙 통과율로 캠페인 점수 계산. 이전 추정 기록은 `legacy_estimate`로 보존·분리 | 점수 근거가 명확해짐. 산식이 바뀌었으므로 이전 대비 상승·하락을 성능 변화로 해석하면 안 됨 |
| 수집 실패 처리 | Map 실패는 캠페인 실패로 처리했지만, 각 URL의 실제 오류는 확인하지 않음 | 실제 404, Map 429, 취소, 부분 성공, 미수집 값을 구분 | 일부 페이지의 실패가 정상 수집처럼 보이는 문제를 줄임 |
| 페이지별 수정 작업 | 큐샵 페이지의 현재 값과 수정안을 관리하는 전용 작업대 없음 | 제목·검색 설명·대표 URL·OG 이미지·robots·JSON-LD의 현재 값, 수정안, 이유, 근거를 저장 | 여러 담당자가 참고할 명확한 수정 지시서 제공. 본문 편집·자동 게시까지 포함하지 않음 |
| 승인과 충돌 검사 | GEO Blocks의 스펙 승인과 별개로, 실제 큐샵 페이지를 기준으로 하는 승인·전달 흐름은 없음 | 승인자·시각을 기록하고 승인 및 안내 다운로드 직전에 페이지를 다시 수집. 원본 변경 시 충돌 처리 | 오래된 원본에 기반한 수정안을 전달할 가능성을 줄임. 승인자 이름은 인증된 사용자 권한을 대신하지 않음 |
| 큐샵 적용 방식 | 큐샵 편집기별 적용 안내 없음 | 기존 사이트·신형 블로그·일반 사이트를 구분하고 Markdown 적용 안내 생성 | 적용 위치와 제약을 안내. 관리자 로그인, 쓰기 API 연결, 자동 게시 기능은 없음 |
| 반영 완료 판단 | 페이지 SEO 수정안의 실제 반영을 필드별 확인하는 절차 없음 | 공개 HTML과 승인한 필드를 비교해 확인 완료·반영 대기·충돌·실패를 구분 | 다운로드나 HTTP 200만으로 완료 처리하지 않음. 승인 범위 밖 본문 변경도 충돌로 처리하므로 재승인이 필요할 수 있음 |
| 구조화 데이터 | Studio·GEO Blocks에 FAQ·엔티티 등 JSON-LD 생성 기능이 있었음 | Product·Organization·WebSite·WebPage·BlogPosting·BreadcrumbList 기본 제안과 공개 본문 근거·원본 값·중복 유형·ID 검사 추가 | 근거 없는 가격·평점·작성자 등과 중복 생성을 제한. 지원 필드가 제한된 검증이며 완전한 Rich Results 검증기는 아님 |
| AI 안내 파일의 범위 | 문서 CRUD·다운로드·루트 `/llms.txt` 원격 확인 지원 | 하위 경로, `llms-ko.txt`·`ai.txt`·`ai-ko.txt`, 한국어·영어 구분, 저장 이력과 버전 비교 지원 | 사이트 구조별 파일 관리 가능. 언어 지정은 자동 번역이 아니며 ZIP 묶음 배포는 없음 |
| AI 파일 게시 확인 | 원격 파일 형식이 유효하면 배포 상태로 처리하고 원격 내용으로 저장 문서를 교체 | HTTP·MIME·문서 형식·내용 해시 일치를 검사하고 원격 파일을 초안과 별도 보관 | 다른 파일이나 HTML 오류 페이지를 게시 성공으로 오인하는 문제를 줄이고 로컬 초안을 보호 |
| 진단 규칙 해석 | 요약 없는 llms 문서를 오류 처리하고, FAQ가 없는 페이지에도 FAQ·FAQPage 실패를 부여. AI 봇 정책을 한 범주로 점검 | 요약을 선택 품질 안내로 변경하고 FAQ 없는 페이지는 필수 실패에서 제외. 검색·학습·사용자 요청 봇 정책을 구분하고 규칙 버전 기록 | 페이지 목적과 정책 차이를 반영. robots 정책 관측이 실제 봇 방문이나 인용을 증명하지는 않음 |
| AI 지표와 전후 비교 | 모델 답변 측정과 기존 Google AI Overview 관측은 있었지만 대시보드의 직전 측정 비교에 조건 일치 검사가 없었음 | 모델 답변은 `model_only`, 기존 AIO는 `serp_snapshot`으로 명시. 질문·모델·브랜드·반복 수·언어 등 조건이 같은 실측끼리 비교하고 SERP의 mock/live를 분리 | 조건 변경으로 생긴 차이를 개선 효과로 오인하는 문제를 줄임. 과거 조건 정보가 없는 기록과는 증감 비교 불가 |
| 수집 비용과 범위 | Firecrawl 키와 Map당 25개 URL 제한 존재 | API 키 없는 개별 URL 수집 추가. Map 월간 요청 시도 한도, 동일 요청 중복 방지, 본문 요청 동시성 3, 직접 수집 캠페인당 50개 URL 제한 | 소규모 확인을 쉽게 시작하고 중복 Map 호출을 제한. 월간 예약량은 실제 청구액과 다름 |
| 데이터 보관과 복구 | 기존 업무 데이터와 JSON 워크스페이스 내보내기 중심 | 페이지 근거·수정안·승인·작업·AI 파일 이력 테이블 추가, DB 마이그레이션 v13과 SQLite 전체 백업 명령 추가 | 운영 과정까지 보관. 기존 JSON 백업에는 새 사이트 운영 테이블과 전체 AI 파일 이력이 포함되지 않아 전체 복구에는 SQLite 백업 필요 |

**특히 달라진 점의 해석**

1. **기능 추가와 함께 측정 신뢰성이 교정됐다.** SEMForge 사이트 진단의 과거 HTTP 200은 실제 응답을 확인한 값이 아니었다. 이제 실제 응답과 수집 실패를 저장하므로 문제 페이지를 판단할 근거가 생겼다. 이는 앱 전체가 이전에 실측 기능이 없었다는 뜻은 아니다.
2. **작업 완료 기준이 명확해졌다.** 예를 들어 페이지 제목 수정안을 내려받은 뒤 큐샵에 반영하지 않으면 ‘반영 대기’가 된다. 승인한 제목이 공개 HTML에 나타나고 다른 충돌이 없어야 ‘확인 완료’가 된다.
3. **현재 건강 점수는 범위가 좁다.** 캠페인 점수에 들어가는 기술 규칙은 현재 HTML 제목 존재와 JSON-LD 문법 오류 여부다. 설명·대표 URL·구조화 데이터 존재 등은 별도 권고이며, 건강 점수 100점이 전체 SEO/GEO 완성을 뜻하지 않는다. 수집 실패 페이지 수와 상세 진단도 함께 확인해야 한다.
4. **운영 기록은 늘지만 수동 작업은 남는다.** 수정안 작성·승인·재검증 단계가 추가되며 큐샵 관리자에서의 저장·게시도 필요하다. 추적성과 확인 절차의 개선은 확인되지만, 작업시간 절감률은 측정되지 않았다.

**계획 대비 남아 있는 범위**

| 항목 | 현재 상태 | 분석 |
|---|---|---|
| 공개 페이지 수집·수정안·승인·수동 적용 안내·재검증 | 1차 구현 및 관련 테스트 확인 | 이번 접목의 핵심 결과 |
| AI 파일 관리 | 경로·선택 파일·언어·이력·내용 검증 구현 | 자동 번역·ZIP 묶음 배포는 포함되지 않음 |
| 큐샵 자동 게시 | 미구현 | 수동 안내 다운로드를 외부 게시 완료로 표현하면 안 됨 |
| Google Search Console 성과 연동 | 후속 단계 | 클릭·노출·CTR의 실제 전후 개선을 이 접목만으로 판단할 수 없음 |
| 서버/CDN 봇 로그 수집 | 후속 단계 | 봇 정책과 실제 봇 방문 횟수는 별도 데이터 |
| 새 웹 검색형 AI 인용 측정 | 후속 단계 | 기존 Google AI Overview 관측은 재사용하고 있으나, 모델 답변에 새 웹 검색 citation 호출을 붙인 것은 아님 |
| CTA·폼·전환 집계 | 후속 단계 | 매출·문의 증가를 증명하는 데이터 연결은 남아 있음 |
| 다중 고객 SaaS와 권한 체계 | 기존 로컬 단일 워크스페이스 범위 유지 | 프로젝트별 데이터 검사와 인증·테넌트 격리를 구분해야 함 |

따라서 구현 범위는 기획서의 공개 페이지 운영 흐름을 중심으로 한 1차 적용이다. 전체 6~8주 로드맵의 완료율이나 실제 사업 성과 향상률을 임의로 산출할 근거는 없다.
