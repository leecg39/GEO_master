# GEO Master × claude-seo 구현 기록

## 범위

사용자 제공 [원본 계획서](./GEO_master_Claude_SEO_Integration_Plan.md)의 15절에 따라 1차 진단 기반, 2차 승인 기준선·변경 감지를 순서대로 구현한다. 6주 로드맵 전체를 완료했다고 표시하지 않는다. 기존 Qshop 미커밋 작업과 v13 마이그레이션을 유지한다.

## 1단계

- `src/lib/seo/`: 스냅샷을 공유하는 기술·스키마 분석기, 고정 실행 목록, 4가지 상태, 규칙 버전·근거·설정 해시, 관측 가능한 검사만 포함한 점수.
- `src/lib/site-ops/snapshots.ts`: 분석 결과를 스냅샷에 저장. 기존 boolean rules는 호환 유지. `@graph` 컨텍스트와 복수 유형 처리. 실제 오류 HTTP HTML도 원본 보존.
- `src/lib/url-security.ts`: SEO 관련 응답 헤더만 선별 수집. 쿠키·인증 헤더 제외.
- `src/lib/semforge/siteaudit/index.ts`: 확정 실패만 기존 이슈에 투영. 점수와 검사 범위·규칙 버전을 함께 제공.
- 기존 사이트 작업대에 근거·미확인·해당 없음 표시를 추가.
- DB v14: 기존 스냅샷·캠페인·이슈 테이블에 분석 및 출처 열 추가. 이전 결과를 현재 버전 결과로 추정 변환하지 않음.

검증: 변경 전 39개 파일/217개 테스트, 1단계 후 40개 파일/224개 테스트 통과. `typecheck`, `lint`, `build` 통과.

제한: 작은 결정적 규칙 세트(title, HTTP, JSON-LD 문법·유형·동일 ID)를 제공한다. Google 전체 리치 결과 인증이나 내용의 사실성 자동 판정을 제공하지 않는다. 기존 편집 사실성 게이트는 유지한다. `/audit`의 32항목 GEO 점수와 `audit_items` 전환, Studio Improve/New, 외부 GSC/성능 공급자 연결은 후속 로드맵이다.

## 2단계

- `src/lib/seo/drift.ts`: 승인 전 원본과 승인 후 새 수집을 비교하는 순수 함수. 승인대로 반영/반영 대기/예상 밖 변경/비교 불가를 분리한다.
- 기준선은 `change_sets.snapshot_id + approved_at`를 재사용한다. 수집 실패·404·단순 전달을 정상 기준선으로 승격하지 않는다.
- 제목·설명·canonical·메타 이미지·robots·JSON-LD 외에 본문 해시, HTTP 색인 정책, 본문 제목, 최종 도착 URL을 보호한다. 원본 HTML 해시 변화만으로 충돌을 만들지 않는다.
- JSON 객체 키와 robots 토큰 순서는 공통 정규화 함수로 비교한다. URL 마지막 슬래시와 쿼리를 유지하며, Firecrawl Map의 무조건적인 추적 파라미터 제거를 없앴다.
- DB v15의 `seo_drift_events`와 변경안 상태를 같은 트랜잭션에서 저장한다. 동일 스냅샷의 중복 이벤트는 차단하고 이전 재검증 이력은 유지한다.
- 기존 승인 카드에서 기준/새 수집 ID, 변경 분류와 값, 이력을 확인할 수 있다. 조회는 활성 프로젝트·캠페인·변경안으로 제한한다.
- 독립 검토 보완: 공백 스키마 유형 차단, 근거 없는 pass/fail 모두 unknown 처리, 빌드가 변경한 `next-env.d.ts`만 원상 복구.

검증: 최종 41개 파일/246개 테스트 및 타입 검사·린트·빌드를 모두 통과했다. 실행 결과는 [검증 기록](./verification.json)을 따른다. 첫 실행에서 네트워크 실패가 freshness로 분류된 1건을 발견해 collection 검사 우선순위로 수정했다. 실제 서비스 DB 백업은 `data/backups/`에 유지했다. 브라우저 QA는 별도 `/tmp/geo-claude-seo-ui-qa.db`로 실행했다.

| 검증 시나리오 | 결과 |
| --- | --- |
| 승인 제목 반영 + 새 noindex 동시 발생 | 제목 expected, robots unexpected, conflict |
| 승인 전 값이 그대로 공개됨 | pending, verification_pending |
| JSON-LD 키 순서·robots 순서·원문 HTML 잡음 | 의미 필드가 같으면 충돌 없음 |
| canonical 삭제·슬래시·쿼리 변경 | unexpected 이력 |
| 실패·404·옛 스냅샷·다른 수집 조건 | unknown, verified 금지 |
| 프로젝트·캠페인 간 변경안/이력 조회 | 차단 |
| 새 재검증과 이전 이력 | 승인 기준 유지, 과거 이벤트 보존 |
| 기존 데이터와 v15 마이그레이션 | 데이터 보존, 외래키 검사 정상 |

후속 로드맵: `/audit`의 기존 32항목 계약 전환, 전체 타입별 리치 결과 검사, 독립적인 정기 기준선 모니터링, 전략 작업 카드·Studio Improve/New·GSC/성능 API는 이번 15절의 1·2단계 범위에 포함하지 않았다. 외부 큐샵 사이트에 실제 게시하거나 검색 순위·성과를 검증한 것은 아니다.

## 최종 검토 보완

- [2단계 검토](./chatgpt-stage2-review.md)에서 발견한 진단 버전 결합을 제거했다. 게시 결과는 실제 메타데이터로 비교하므로 진단 버전·설정 해시가 달라지거나 이전 분석 결과가 없어도 비교할 수 있다. 프로젝트·캠페인·대상 URL, 수집 성공·시점, 파서·렌더링 방식·언어 검사는 유지한다.
- 순수 비교 테스트와 실제 승인 → 전달 → 재검증 통합 테스트에서 이전 분석 결과가 없는 기준선도 정상 검증되고 승인 기준이 유지되는지 확인했다.
- JSON-LD의 `@id` 참조와 문맥에서 추론되는 유형을 확정 오류로 처리하지 않는다. 직접 선언된 공백·잘못된 유형은 실패로 판정하고, 직접 확인할 수 없는 유형은 미확인으로 남긴다. 근거: [W3C JSON-LD 1.1 노드 식별자](https://www.w3.org/TR/json-ld11/#node-identifiers), [유형 지정](https://www.w3.org/TR/json-ld11/#specifying-the-type).
- [3차 검토](./chatgpt-stage3-review.md)에서 승인된 스키마 오류 수정이 파싱 오류 감소 때문에 충돌로 처리되는 문제를 발견했다. 승인 JSON-LD가 정확히 반영되고 남은 파싱 오류가 0이면 정상 수정으로 인정한다. 오류가 남으면 개수가 이전과 같아도 검증을 차단하며, 비승인 상태 변경은 계속 충돌로 처리한다.
- 정상 스키마 수정과 잔여 오류에 대한 순수 비교·승인부터 검증까지의 통합 시나리오를 추가했다. 최초 실행의 244개 통과/2개 실패는 과거 기준선을 최신 스냅샷 목록에서 찾던 테스트 조회 오류였으며, ID로 보존된 스냅샷을 직접 확인하도록 수정했다.
- [ChatGPT 최종 검토](./chatgpt-final-review.md): `DONE` (4차). 계획서 15절의 1·2단계 범위에서 추가 수정이 필요한 결함을 발견하지 못했다는 판정을 받았다.
