# haloX 1차 통합 이후 실행 계획

이번 범위는 기회·라이브러리·스튜디오·전후 추적까지다. 다음 우선순위는 **Google 데이터 자동 수집 → 검색어와 질문 연결 → 통합 기회 분석**이다. 기존 계정의 공유 프로젝트 구조와 GEO 지표는 유지한다.

## 현재 구현에서 출발할 지점

- `src/lib/search-console/store.ts`는 GSC 내보내기 파일의 기간·속성·일별·검색어/페이지 등 차원 데이터를 프로젝트별로 저장한다. 파일 해시로 중복을 방지한다.
- `src/app/api/search-console/imports/route.ts`와 `/search-console`은 수동 가져오기·조회 흐름을 제공한다.
- `src/app/api/analytics/overview/route.ts`는 SEMForge 도메인 개요다. GA4 연동 완료로 간주하거나 GA4 데이터처럼 표시하지 않는다.
- `src/lib/opportunities.ts`는 저장된 AI 응답 기반 후보와 근거 이력을 제공한다. 새 검색 데이터 분석은 별도 출처·유형으로 추가한다.

## 단계 1 — Google GSC·GA4 수집 기반

시작 시 공식 API 문서·OAuth 요구사항·쿼터를 다시 확인하고 계약을 확정한다. 실제 Google 계정 연결에는 사용할 속성과 읽기 권한이 필요하다.

1. 프로젝트별 Google 연결·GSC 속성·GA4 속성을 명시적으로 선택한다. 인증 토큰은 기존 서버 암호화 방식을 재사용하고 백업에서 제외한다.
2. 수동 파일 가져오기를 유지하면서 API 수집 소스·기간·필터·수집 시각·완료 상태를 기록한다. GSC의 집계 차원과 GA4의 세션/전환은 서로 다른 데이터셋으로 저장한다.
3. 날짜 구간별 재수집·페이지네이션·쿼터 지연·권한 만료를 처리한다. 기간·속성·차원 키로 멱등 upsert하고 지연 데이터는 표시한다.
4. 서버 작업은 시작 프로젝트와 연결 버전을 고정한다. 실행 중 프로젝트 전환·연결 해제·워크스페이스 교체 시 다른 프로젝트에 저장되지 않아야 한다.

완료 기준: 대역 서버 계약 테스트, 중복 수집·부분 실패·권한 만료·복원 경합 테스트, 사용자가 연결한 한 속성의 실제 읽기 smoke, 기존 XLSX 가져오기 회귀 통과. 운영 일일 예약은 수동 동기화 검증 후 활성화한다.

## 단계 2 — 검색어 ↔ 질문 ↔ 페이지 매핑

1. 프로젝트에 귀속되는 다대다 매핑을 추가한다. 검색어, 질문, 대상 페이지를 연결하고 출처·작성자 유형·수정 시각을 보존한다.
2. 최초 버전은 사용자가 확인하는 수동 매핑과 정규화 일치 제안을 제공한다. 유사하다는 이유만으로 서로 다른 검색 의도를 자동 확정하지 않는다.
3. 질문·자료 원본 삭제 시 표시와 스냅샷을 보존한다. 워크스페이스 export/import의 스키마와 ID 재매핑도 함께 확장한다.

완료 기준: 중복/다대다/원본 삭제/동시 수정/다른 프로젝트 접근/백업 왕복 검증. 매핑 전 데이터도 계속 조회 가능해야 한다.

## 단계 3 — 검색·AI 통합 기회

1. GSC 노출이 확인되지만 클릭률이 낮은 페이지, 실제 검색 수요와 AI 언급 공백이 겹치는 질문을 설명 가능한 규칙으로 제안한다.
2. 검색어·국가·기기·기간·AI 모델·질문 표본을 함께 표시한다. GSC의 누락·익명화·기간 차이와 AI 실패를 0점으로 취급하지 않는다.
3. 기존 기회 채택·스튜디오·수동 반영·후속 측정을 재사용한다. 기존 GEO 점수를 새 단일 점수로 대체하지 않는다.
4. 후보 생성은 저장 데이터만 사용한다. 새 유료 측정이 필요하면 별도 기존 측정 흐름에서 비용을 확인한다.

완료 기준: 실제 저장 데이터로 판정 이유를 재현 가능, 중복 후보 방지, 기간/조건 불일치 경고, 전후 결과의 인과효과 단정 방지.

## 운영 확인 순서

1. 최신 백업을 확보한 스테이징에서 마이그레이션 32·33과 schema v3 복원을 확인한다.
2. `GEO_ENABLE_HALOX=1`로 내부 프로젝트에 기회 → 채택 → 자료/페르소나 → 초안 검토 → 수동 반영 → 재측정 흐름을 적용한다.
3. Provider 비용·오류·중복 실행 상태를 확인한 뒤 운영 활성화를 판단한다. 문제가 있으면 플래그를 끄고 데이터를 보존한다.

운영 배포·실제 계정 연결은 이번 커밋·푸시와 별개다. 고객사별 SaaS 격리·다국어 발행·MCP·파일 파싱은 이 세 단계 이후 별도 설계한다. 기간 추정은 Google 연결·데이터량을 확인한 뒤 정한다.
