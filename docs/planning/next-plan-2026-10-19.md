## N1. 계정별 워크스페이스 분리

현재 `projects`와 `settings.active_project_id`는 모든 로그인 계정이 공유한다. 보고서에 추가한 활성 프로젝트 필터는 다른 프로젝트 ID의 직접 조회를 막지만, 계정별 데이터 격리를 제공하지는 않는다.

1. 기존 공용 프로젝트의 귀속과 팀 공유 정책을 확정한다. 최초 접속 계정에 기존 프로젝트를 자동 귀속시키지 않는다.
2. 프로젝트 소유·멤버십과 계정별 활성 프로젝트를 추가하는 비파괴 마이그레이션을 설계한다. 기존 데이터는 보존하고 귀속 전에는 관리자만 관리하도록 한다.
3. `projects.ts`에서 조회·생성·전환·복제·삭제 권한을 공통 적용한다. `settings.ts`의 브랜드 읽기와 서버 페이지 렌더링도 같은 계정 문맥을 사용한다.
4. 프로젝트별 API·예약 작업·WordPress 연결·Search Console·보고서·백업 가져오기/복원·공개 공유 링크의 경계를 점검한다. 백그라운드 작업은 생성 당시 소유 문맥을 저장한다.
5. 서로 다른 두 계정의 동시 프로젝트 전환·직접 ID 접근·다운로드·복원에서 교차 데이터가 0건인지 검증한다. 관리자·게스트·회원가입 계정·로컬 모드의 호환성을 확인한다.

완료 기준: 계정 A가 계정 B의 프로젝트를 목록·선택·조회·수정·내보내기할 수 없으며, 두 계정의 활성 프로젝트 전환이 서로 영향을 주지 않는다.
