# GEO_master × haloX 잔여 구현·검토 계획과 결과

기준: `2a7b69f`의 GEO_master와 사용자가 승인한 haloX 선별 이식 계획. 기존 SQLite·인증·네 Provider·공유 활성 프로젝트 운영은 유지한다.

## 실행 순서

1. 기존 구현을 요구사항별로 확인하고 데이터 유실·동시성·백업 호환의 반례를 만든다.
2. 적대적 검토를 코드 품질(Standards), 승인 계획 충족(Specification) 두 축으로 수행한다.
3. 재현된 결함을 수정하고 회귀 테스트를 추가한다.
4. 전체 Vitest, typecheck, lint, build와 Ego 데스크톱·모바일 확인을 수행한다.
5. 관련 변경만 커밋·푸시하고 후속 Google 연동 계획을 남긴다.

## Standards 검토 결과

별도 읽기 전용 검토자가 확인했다.

- **P1 해결 — 예전 수동 JSON의 백업 복원 실패:** 완전한 생성 문맥만 구조적으로 인식하여 재매핑한다. 임의 값은 그대로 보존하고 인식한 참조는 프로젝트 소유권을 검사한다.
- **P2 해결 — 삭제된 자료 ID가 이력에서 재선택:** 최초 URL 진입·이력 클릭 모두 현재 존재하는 자료만 선택한다. 과거 문맥 스냅샷은 변경하지 않는다.
- 수정본 재검토에서 추가 실질 결함 없음. 독립 실행한 당시 통합 테스트 36개 통과.
- **브라우저 발견 후 해결 — 콘텐츠 직접 링크의 SSR 오류:** 처음 열린 상세창의 Portal을 클라이언트 준비 후 생성한다. 모달 회귀 테스트 4개와 실제 `/studio?contentId=1` 새로고침에서 오류 없이 상세 표시를 확인했다. 별도 재검토에서도 잔여 지적 없음.

## Specification 검토 결과

승인 계획을 기준으로 별도 읽기 전용 검토자가 확인했다.

- **P1 해결 — 생성 중 교체 복원 후 이전 결과 오염:** 실행마다 고유 토큰을 부여하고 결과 저장 트랜잭션에서 유효성을 검사한다. 같은 프로젝트/요청 ID를 재사용한 복원도 구분한다.
- **P2 해결 — 삭제된 기준 근거가 갱신으로 교체:** 원본이 유실된 후보는 기존 스냅샷을 유지한다.
- **P2 해결 — 후속 근거 부분 삭제 후 재저장:** 후속 실행 스냅샷을 보존하고 같은 연결은 재집계하지 않는다. 삭제 표시와 원래 분모가 유지된다.
- 마지막 결함의 독립 재현·추가 회귀 테스트 각각 통과. 수정 범위의 잔여 지적 없음.
